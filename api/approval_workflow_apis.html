🔄 Approval Workflow APIs

Hierarchical Multi-Level Approval System for Employee, HR, Supervisor & Sub-Company Creation

Smart routing ensures approval requests go only to relevant company managers

📋 System Overview

✨ Key Features

  • Hierarchical Approvals: Multi-level approval chains based on account type
  • Smart Routing: Requests go only to the relevant company's manager
  • Auto-Stop on Rejection: If sub-manager rejects, main manager isn't notified
  • Real-time Notifications: Automated notifications to next approvers
  • Complete Audit Trail: Track every action in the approval workflow
  • Expiration Management: Pending requests expire after 30 days

🔒 Security & Access Control

  • JWT Authentication Required: All endpoints require valid Bearer token
  • Role-Based Access: Only authorized roles can create/approve requests
  • Company-Specific Routing: Managers only see requests for their company
  • Permission Validation: Each action verifies user permissions

📝 Create Approval Requests

POST /api/approval-workflow/create-employee-request/
Create an employee account approval request. HR can submit new employee details which will go through the approval chain: Sub-Company Manager → Main Company Manager.
🔐 Who Can Use:
  • HR (in any company)
  • Manager (main or sub-company)
  • Sub-Manager
📥 Request Body:
{ "employee_data": { "full_name": "John Doe", "employee_code": "EMP001", "date_of_birth": "1990-01-15", "gender": "M", "marital_status": "S", "mobile_number": "+1234567890", "email": "john.doe@company.com", "current_address": "123 Main St", "permanent_address": "123 Main St", "role": "Employee", "sub_company_id": 5 // Optional: if creating in sub-company }, "official_details_data": { "date_of_joining": "2025-01-01", "department": "Engineering", "designation": "Software Engineer", "location": "New York", "supervisor_name": "Jane Manager", "salary_type": "MONTHLY" }, "password": "TempPassword123" }
📤 Response:
{ "success": true, "message": "Employee creation request submitted. Awaiting Sub-Company Manager approval.", "data": { "workflow_id": 123, "approval_type": "employee", "current_stage": "sub_manager", "status": "pending" } }

💡 Smart Routing

  • If employee is for Sub-Company 1 → Notification goes to Sub-Company 1 Manager only
  • After sub-company approval → Goes to Main Company Manager
  • If employee is for Main Company directly → Starts at Main Company Manager
POST /api/approval-workflow/create-hr-supervisor-request/
Create HR or Supervisor account approval request. Requires 3-level approval: Sub-Company Manager → Main Company Manager → Admin.
🔐 Who Can Use:
  • Manager (main or sub-company)
  • Sub-Manager
📥 Request Body:
{ "employee_data": { "full_name": "Sarah HR", "employee_code": "HR001", "date_of_birth": "1988-05-20", "gender": "F", "marital_status": "M", "mobile_number": "+1234567891", "email": "sarah.hr@company.com", "current_address": "456 Oak Ave", "permanent_address": "456 Oak Ave", "sub_company_id": 5 // Optional }, "official_details_data": { "date_of_joining": "2025-02-01", "department": "Human Resources", "designation": "HR Manager", "location": "Chicago", "supervisor_name": "Director Name", "salary_type": "MONTHLY" }, "password": "TempHRPass123", "account_type": "hr" // or "supervisor" }
📤 Response:
{ "success": true, "message": "HR creation request submitted. Awaiting Main Company Manager approval.", "data": { "workflow_id": 124, "approval_type": "hr", "current_stage": "main_manager", "status": "pending" } }
POST /api/approval-workflow/create-sub-company-request/
Create a sub-company approval request. Only requires Admin approval (1 level).
🔐 Who Can Use:
  • Manager (main company only)
📥 Request Body:
{ "company_data": { "name": "Tech Division", "address": "789 Tech Park", "contact_number": "+1234567892", "email": "tech@company.com", "gst_number": "GST123456", "pan_number": "PAN123456" } }
📤 Response:
{ "success": true, "message": "Sub-company creation request submitted. Awaiting Admin approval.", "data": { "workflow_id": 125, "approval_type": "sub_company", "current_stage": "admin", "status": "pending" } }

📋 View Pending Approvals

GET /api/approval-workflow/pending-approvals/
Get all pending approval requests that the current user can approve. Smart filtering ensures you only see requests for your company.
🔐 Access Rules:
  • Admin: Sees all workflows at "admin" stage
  • Main Company Manager: Sees workflows at "main_manager" stage for their company only
  • Sub-Company Manager: Sees workflows at "sub_manager" stage for their sub-company only
📊 Query Parameters:
Parameter Type Required Description
type string Optional Filter by type: employee, hr, supervisor, sub_company
page integer Optional Page number (default: 1)
page_size integer Optional Items per page (default: 20)
📤 Response Example:
{ "success": true, "data": [ { "id": 123, "approval_type": "employee", "approval_type_display": "Employee Creation", "status": "pending", "current_stage": "sub_manager", "current_stage_display": "Awaiting Sub-Company Manager", "company": "TechCorp Inc", "sub_company": "Engineering Division", "created_by": { "employee_code": "HR001", "full_name": "Jane HR", "role": "HR" }, "created_at": "2025-10-08T10:30:00Z", "request_data": { "employee_data": { "full_name": "John Doe", "employee_code": "EMP001", "role": "Employee" } } } ], "pagination": { "page": 1, "page_size": 20, "total_count": 5, "total_pages": 1 } }

✅ Approve / ❌ Reject Requests

POST /api/approval-workflow/{workflow_id}/approve/
Approve a pending workflow request. If this is the final approval stage, the employee/company will be created automatically.
📥 Request Body:
{ "comments": "Approved. All details verified." // Optional }
📤 Response (Intermediate Stage):
{ "success": true, "message": "Approved. Request moved to Main Company Manager stage.", "data": { "workflow_id": 123, "status": "pending", "current_stage": "main_manager" } }
📤 Response (Final Approval):
{ "success": true, "message": "Employee Creation has been approved and created successfully.", "data": { "workflow_id": 123, "status": "approved", "current_stage": "completed" } }

✨ What Happens on Final Approval:

  • User account is created with provided credentials
  • Employee record is activated in the system
  • Official details are linked to the employee
  • Creator receives success notification
  • Pending user record is cleaned up
POST /api/approval-workflow/{workflow_id}/reject/
Reject a pending workflow request. This immediately stops the workflow and prevents further approvals.
📥 Request Body:
{ "reason": "Incomplete documentation provided" // Required }
📤 Response:
{ "success": true, "message": "Request rejected successfully. Workflow stopped.", "data": { "workflow_id": 123, "status": "rejected", "rejection_reason": "Incomplete documentation provided" } }

⚠️ Rejection Behavior:

  • Workflow stops immediately - no further approvals needed
  • Next level approvers are NOT notified
  • Creator receives rejection notification with reason
  • Pending user data is retained for 30 days then auto-deleted
  • Rejection is permanent - cannot be undone

💡 Complete Flow Examples

Example 1: HR Creates Employee in Sub-Company 1
# Step 1: HR (in Sub-Company 1) creates employee request POST /api/approval-workflow/create-employee-request/ Authorization: Bearer {hr_token} { "employee_data": { "full_name": "John Doe", "employee_code": "EMP001", "email": "john@company.com", "role": "Employee", "sub_company_id": 1 // Sub-Company 1 }, "password": "temp123" } # Response: Workflow created, notification sent to Sub-Company 1 Manager ONLY { "workflow_id": 100, "current_stage": "sub_manager" }
# Step 2: Sub-Company 1 Manager approves POST /api/approval-workflow/100/approve/ Authorization: Bearer {sub_company_1_manager_token} { "comments": "Approved by Sub-Company 1 Manager" } # Response: Moved to main_manager stage # Notification sent to Main Company Manager { "current_stage": "main_manager" }
# Step 3: Main Company Manager approves (Final) POST /api/approval-workflow/100/approve/ Authorization: Bearer {main_manager_token} { "comments": "Final approval - Employee account created" } # Response: Employee created successfully! { "status": "approved", "current_stage": "completed", "message": "Employee has been approved and created successfully." }
Example 2: Sub-Company Manager Rejects Employee
# Step 1: HR creates employee request (same as above) # Step 2: Sub-Company 1 Manager REJECTS POST /api/approval-workflow/100/reject/ Authorization: Bearer {sub_company_1_manager_token} { "reason": "Incomplete documentation" } # Response: Workflow stopped { "status": "rejected", "message": "Request rejected successfully. Workflow stopped." } # Result: # - Main Company Manager is NOT notified # - Creator (HR) receives rejection notification # - Workflow permanently rejected
Example 3: Manager Creates HR Account (3-Level Approval)
# Step 1: Manager creates HR request POST /api/approval-workflow/create-hr-supervisor-request/ Authorization: Bearer {manager_token} { "employee_data": { "full_name": "Sarah HR", "employee_code": "HR002", "sub_company_id": 1 }, "account_type": "hr", "password": "hrtemp123" } # Step 2: Sub-Company Manager approves → Goes to Main Manager # Step 3: Main Company Manager approves → Goes to Admin # Step 4: Admin approves (Final) → HR account created!
