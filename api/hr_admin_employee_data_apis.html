🔐 Role-Based Access Control

Different roles have different levels of access to employee data:

👑 Admin

Can manage all employees across all companies

📊 Manager

Can manage employees in main company and sub-companies

🏢 Sub-Manager

Can manage employees only in their sub-company

👥 HR

Can manage employees in their company

👁️ Supervisor

Can manage employees in their company

📝 1. Official Details APIs

POST
/api/employee-data-management/add-official-details/
Add official employment details including date of joining, department, designation, location, and supervisor information.
✓ Admin | Manager | Sub-Manager | HR | Supervisor
PUT
/api/employee-data-management/update-official-details/
Update existing official details. Supports partial updates - only send the fields you want to change.
✓ Admin | Manager | Sub-Manager | HR | Supervisor

Request Body Example:

{ "employee_id": 1, "date_of_joining": "2024-01-15", "department": "IT Department", "designation": "Senior Developer", "location": "Bangalore Office", "supervisor_name": "Jane Smith", "salary_type": "MONTHLY" }

🆔 2. Identity Documents APIs

POST
/api/employee-data-management/add-identity-documents/
Add government-issued identity documents including Aadhaar, PAN, ESI, PF UAN, and passport numbers.
✓ Admin | Manager | Sub-Manager | HR | Supervisor
PUT
/api/employee-data-management/update-identity-documents/
Update existing identity document numbers. Useful when documents are renewed or corrected.
✓ Admin | Manager | Sub-Manager | HR | Supervisor

Request Body Example:

{ "employee_id": 1, "aadhaar_number": "1234 5678 9012", "pan_number": "ABCDE1234F", "esi_number": "1234567890", "pf_uan_number": "100123456789", "passport_number": "A12345678" }

Important Notes:

  • Aadhaar: 12 digits (spaces allowed)
  • PAN: 10 alphanumeric characters
  • ESI: Optional, 10-17 digits
  • PF UAN: 12 digits
  • Passport: Optional, alphanumeric

🏦 3. Bank Details APIs

POST
/api/employee-data-management/add-bank-details/
Add bank account details for salary disbursement including bank name, account number, IFSC code, and branch information.
✓ Admin | Manager | Sub-Manager | HR | Supervisor
PUT
/api/employee-data-management/update-bank-details/
Update bank account details when an employee changes their bank or account.
✓ Admin | Manager | Sub-Manager | HR | Supervisor

Request Body Example:

{ "employee_id": 1, "bank_name": "State Bank of India", "account_number": "1234567890123456", "ifsc_code": "SBIN0001234", "branch_name": "Main Branch, Bangalore" }

Field Requirements:

  • Account Number: 9-18 digits
  • IFSC Code: Exactly 11 characters (format: XXXX0YYYYYY)
  • All fields are mandatory

📊 4. Retrieve Employee Data APIs

GET
/api/employee-data-management/get-employee-details/?employee_id=1
Get complete employee details including personal info, official details, identity documents, and bank details in a single API call.
✓ Admin | Manager | Sub-Manager | HR | Supervisor
GET
/api/employee-data-management/list-employees/
List all employees based on role permissions. Supports filtering by company, role, and status.
✓ Admin | Manager | Sub-Manager | HR | Supervisor

Query Parameters for list-employees:

  • company_id (optional) - Filter by specific company
  • role (optional) - Filter by employee role (Admin, Manager, HR, Supervisor, Employee)
  • status (optional) - Filter by status (ACTIVE, LEFT, TERMINATED)

Example URLs:

# List all employees GET /api/employee-data-management/list-employees/ # List only HR employees GET /api/employee-data-management/list-employees/?role=HR # List active employees in company 5 GET /api/employee-data-management/list-employees/?company_id=5&status=ACTIVE

📄 Document Management APIs

Upload, update, and manage employee documents (Appointment Orders, ESI Cards, ID Cards, Relieving Letters)

POST
/api/employee-document-management/upload-document/

Upload a document for an employee

Form Data:

employee_id: 19
doc_type: APPOINTMENT
file: [PDF/Image file]
issued_date: 2024-01-15

Document Types:

  • APPOINTMENT - Appointment Order
  • ESI_CARD - ESI Card
  • ID_CARD - ID Card
  • RELIEVING - Relieving Letter

Response (201 Created):

{
  "message": "Document uploaded successfully",
  "data": {
    "id": 1,
    "doc_type": "APPOINTMENT",
    "doc_type_display": "Appointment Order",
    "file": "employee_documents/appointment_emp19.pdf",
    "file_url": "http://localhost:8000/media/...",
    "issued_date": "2024-01-15"
  }
}

Python Example:

import requests

url = 'http://localhost:8000/api/employee-document-management/upload-document/'
headers = {'Authorization': f'Bearer {hr_token}'}

with open('appointment_order.pdf', 'rb') as file:
    files = {'file': file}
    data = {
        'employee_id': 19,
        'doc_type': 'APPOINTMENT',
        'issued_date': '2024-01-15'
    }
    response = requests.post(url, headers=headers, files=files, data=data)
    print(response.json())

📋 Document Management Workflow

  1. HR uploads appointment order for new employee using upload-document API
  2. Employee receives notification (can be implemented)
  3. Employee views documents via employee-documents APIs (read-only)
  4. Employee downloads required documents as PDF
  5. HR updates document if changes needed using update-document API
  6. HR deletes old document if needed using delete-document API

Note: Employees can only view/download their own documents. HR/Admin/Manager/Supervisor can upload/update/delete documents for employees they manage.

🔒 Security & Best Practices

  • Always require JWT authentication - All APIs validate user roles
  • Role-based access control - Users can only manage employees within their scope
  • Validate data formats - Aadhaar, PAN, IFSC codes must match specific patterns
  • Encrypt sensitive data - Use HTTPS for all API calls
  • Audit trail - Log all changes to employee data
  • Handle duplicates - APIs prevent duplicate records
  • Partial updates - Use PUT with only changed fields to minimize data transfer
